Privacy policy

This policy describes how Nguyễn Văn Hùng handles information in PO Audit & Stocky Rescue. For privacy questions or a data request, contact support@vievot.com. General app support is available at support@vievot.com.

Information the app handles

  • Shop and authentication information: the shop domain, shop identifiers/name used by Shopify, permission and development-store status, installation state and encrypted Shopify session data. A session can include access/refresh tokens and expiry information. If Shopify provides an online session, its encrypted payload can also contain staff user ID, name, email, locale and account-role/verification flags.
  • Uploaded business records: purchase orders, invoices and receiving records you select. Saved information includes mapped product descriptions and identifiers, quantities, costs, currency, source-row references, column mappings, filenames, file hashes and searchable reference/supplier/date/status fields. Filenames and descriptions can contain personal or business information you enter.
  • Audit and access records: saved reports, source links, creation timestamps, matching identifiers and the first-free-report usage record.

Original uploaded file bytes are parsed in memory and are not saved as an original-file archive by the app. Normalized records and their derived search/report data are saved. The uploaded-file workflow does not import Shopify customer or order records through customer/order API scopes. The current required Shopify scope is read_products. Optional native inventory access is separate and is not required for this uploaded-file workflow.

Why this information is used

The app uses these records to authenticate your shop, compare ordered, received and invoiced merchandise, show source evidence, find saved documents, reopen reports, prevent duplicate imports/runs and enforce current report/plan access. Shopify supplies shop and plan information for those access checks. The app compares merchandise costs; it does not authorize payments or change inventory.

No external AI service is used to parse or compare these records in the current implementation.

Service providers and copies

  • Render runs the application and processes requests and uploads. The current production configuration stores application records in Cloudflare D1 rather than relying on Render's local filesystem.
  • Cloudflare Workers and D1 carry the application's authenticated persistence requests and store the normalized documents, reports, search data, encrypted sessions, usage and installation records. Session payloads are encrypted by the app; this is not a claim that every document field is encrypted by the app.
  • Shopify provides installation, authentication, API and subscription verification, and lifecycle/privacy notifications.

These providers operate their own infrastructure and operational records. The application does not set a guaranteed region or a purge deadline for all provider logs and backups. Cloudflare D1 currently provides a seven-day Time Travel recovery window on the Free plan. Deleting live app records does not promise immediate destruction of every historical provider recovery copy. A recovery window is not a guarantee about all provider retention.

The application deliberately does not write request URLs, headers, uploaded bodies or authentication tokens to access logs. Its Shopify SDK logger suppresses request/token content; startup monitoring uses sanitized status events. This does not mean the hosting providers keep no operational records. The app has no support-ticket database; email threads and copies you have downloaded are outside the app's document deletion controls.

How long information remains and how to delete it

Information or actionCurrent behavior
Saved documents, search data and reportsKept until you delete a document, erase the shop's app data, or an authenticated uninstall/redaction path removes them. The app has no scheduled age-based expiry for these saved records. Temporary save-staging records use an expiring lease and are cleaned opportunistically by later operations, rather than by a guaranteed scheduled purge. Expired authentication tokens are not a general retention deadline for saved documents.
Delete one source documentRemoves that document, its stored derived data and linked reports. The first-free usage record remains. Deletion is available without an active paid plan.
Delete all app dataTyping ERASE in the app removes the shop's documents, reports, sessions and usage. A current installation marker remains so the installation can continue; the operation changes its generation to reject stale writes.
Authenticated uninstall notificationRemoves the shop's documents, reports, sessions and usage. An inactive marker containing shop identity and a generation remains to reject stale authentication and writes. No automatic expiry is set for that marker; authenticated Shopify shop-redact removes it.
Authenticated shop-redact notificationRemoves remaining shop data and the installation marker.
Plan cancellation or verification outageDoes not erase saved documents, reports or first-free usage. Access is checked separately; the first full report remains available. A pending cancellation may remain active until Shopify's actual subscription ends.

Reinstall authentication establishes a fresh installation generation after lifecycle deletion. Exports already saved on your device are not deleted by these app actions. A provider restore can recover older records; a restored environment must be checked against deletion requests before its data is used again.

Your choices and data requests

In Shopify Admin, open the app and use Manage data deletion (always available) to remove a document, or Delete all app data and type ERASE to remove the shop's app data. These actions delete data; they are not needed merely to cancel a plan.

For questions, access requests or help removing uploaded personal information, email support@vievot.com with your shop domain and a description of the request. Avoid sending passwords, tokens or complete invoices in the initial message. Saved reports can be exported as CSV through the app; archive access follows the current plan rules.

Shopify customer-data-request and customer-redact notifications are authenticated and acknowledged. Because the app does not retrieve Shopify customer/order API records or maintain a customer-ID-indexed database, those notifications do not automatically locate or remove arbitrary personal text you uploaded in a filename or business record. Use the document deletion controls or the privacy contact for that content. Authenticated shop-redact uses the shop erasure path described above.
